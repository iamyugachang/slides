03自主化階梯S2

Agent Mode → Cloud Agent → Automation：差異在人的位置

越往右，不只是執行時間變長；觸發方式、檢查點、失敗半徑與適合任務都改變。

Agent Mode

觸發：人下指令
人在迴圈：高頻確認
適合：局部修改、探索、草稿

Cloud Agent

觸發：遠端任務
人在迴圈：里程碑審查
適合：較長工作包、背景執行

Automation

觸發：事件 / 排程
人在迴圈：例外升級
適合：常駐流程、標準化作業
Takeaway：自主化不是把人拿掉，而是重新設計「人在哪裡定義意圖、驗收與例外」。
04能做事的前提S3S4S7

沒有 Spec、Test Strategy、Harness，Agent 只是在更快地產生不確定性

SDD 給出意圖與邊界；Test Strategy 定義信心；Harness 讓執行可重播、可比較、可阻擋。

Spec
任務意圖、約束、完成定義
Test Strategy
信心來源、風險案例、驗收門檻
Harness
隔離環境、重播、比較、阻擋

三個問題要先回答

  • 它要做什麼？Spec 把自然語言意圖轉成可檢查的工作契約。
  • 怎樣算做對？Test Strategy 把「我覺得可以」改成覆蓋與風險信號。
  • 錯了能不能停？Harness 給 Agent 安全沙盒與驗證閘門。
Takeaway：Production Agent 的地基不是 Prompt，而是可驗收、可測試、可回放的工作系統。
05Demo → ProductionS5S8

三個權一開，舊的 Ops、安全、資料治理假設就會失效

從展示到上線，問題不再是「會不會回答」，而是它能決策、能調工具、能跨系統協作之後，誰負責邊界與維運。

自主決策權

Agent 可選擇下一步、重試、放棄或升級。

舊假設：流程分支由人或固定程式碼掌控。

工具調用權

Agent 可呼叫 API、查資料、寫入系統。

舊假設：權限與操作意圖可以事前靜態綁定。

跨系統協作權

Agent 可在多服務、多資料域之間串接任務。

舊假設：系統邊界清楚，責任鏈短且可人工追蹤。
Takeaway：iSearch 類上線經驗提醒我們，Agent 真正的成本常在發布後的監控、回滾、權限與資料品質。
06Agentic InvestigationS6

Agentic Investigation ↔ Human Decision：證據與決策是兩個閉環的接口

Agent 適合高速蒐集、比對、假設驗證；人仍負責判斷風險、取捨、責任與對外溝通。

Agentic Investigation

蒐集線索 → 形成假設 → 查證反例 → 組織 Evidence

Human Decision

確認情境 → 評估風險 → 選擇處置 → 承擔 Decision

↔

Takeaway：不要讓 Agent 直接取代判斷；讓它縮短形成可信證據的時間，並把決策點清楚交還給人。

AgentOps 的重點是讓資產可被發現、可被訂閱、可控版本、可安全下架；否則 Mesh 會變成不可追蹤的暗網。

Takeaway：規模化不是多做幾個 Bot，而是建立 Agent / MCP 的產品目錄、版本紀律與停用機制。
08GAIA 2.0 governanceS9

金融級架構：Marketplace 在上、Gateway 在中，Every-Hop Zero Trust 貫穿每一跳

GAIA 的關鍵不是把所有 Agent 全網狀互連，而是用 Hub-and-Spoke 將 Provider、Consumer、Governance 職責分離。

Marketplace
發現、審核、訂閱 Agent / MCP 資產
Gateway
統一身份、政策、路由、審計
Provider
發布能力與資料契約
Consumer
以 M2M / User Delegation 調用
Governance
政策、風險、稽核與例外審批
M2M / User Delegation + Every-Hop Zero Trust
Takeaway：Hub-and-Spoke 讓金融級治理可集中執行，同時保留資產市場化與跨團隊重用。
09Policy as CodeS10

Policy as Code：把治理放進 Input → Tool → Retrieval → Output 的每個決策點

Agent 的風險不是單一 API 呼叫，而是多步推理與工具鏈。因此政策需要可執行、可測試、可審計。

Default-deny 的意思

不是讓 Agent 不能做事，而是讓每一次越權、跨域、不可逆動作都有明確理由、審批人與審計紀錄。

Takeaway：政策如果只在文件裡，就無法跟上 Agent 的速度；必須變成可部署的程式碼與測試。
