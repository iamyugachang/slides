02PART 1 · 光譜與判準

LLM 讓自動化能處理事先列不完步驟的任務

ETL、CI/CD、排程早就在自動跑。LLM 新增的是：只給目標，也能邊做邊找下一步。

固定流程
程式先排好步驟
ETL · CI/CD · Airflow
＋ LLM
開放任務
「Trino 為什麼變慢？」
要查什麼不能先列完
→
兩種控制方式
Workflow：程式選
Agent：模型選

多做了什麼

OPEN-ENDED TASKS
  • 不必先寫完所有分支，只要先給目標
  • 模型可依查到的結果改變下一步

新增的代價

NEW PROBLEMS
  • 模型會出錯與繞路，結果必須驗證
  • 每一輪都花 token，重試也會增加成本
  • 路徑不固定，較難除錯與追查
步驟越難預先列出，越需要讓模型選下一步。

06PART 2 · Harness 心智模型

模型是大腦；Harness 是身體，工具是手

橘線：模型提出動作，Harness 檢查後執行。藍線：結果寫回模型，模型再決定下一步。

模型負責選

  • 看目前進度與可用工具
  • 提出工具名稱與參數

Harness 負責做

  • 檢查權限與參數，再執行工具
  • 保存結果，交回模型繼續判斷
模型只能提出動作；真正執行與驗證的是 Harness。

09MULTI-AGENT · 四種分工

Multi-Agent 只改分工方式；不自動代表更聰明或更自主

Supervisor

中央 Agent 派工、收結果、決定下一個任務。

適合：需要集中控制與最後整合

Handoff

目前 Agent 直接把控制權與上下文交給下一位。

適合：明確階段交接

Teams

角色固定，共用任務與進度；不一定有唯一主管。

適合：長期穩定分工

A2A

兩個獨立 Agent 系統用協定交換任務與結果。

適合：跨產品或跨組織互通
先決定誰能交棒、誰負責收斂，再決定要不要多 Agent。

3 · FIX

把固定步驟寫成 Workflow

Workflow 主幹＋Agent 插槽

17附錄 03/06 · LANGGRAPH 程式碼

LangGraph：兩個案例都把人審寫成節點

案例 1 · Alert 自動修復
detect → diagnose → approve → heal
from langgraph.types import interrupt

class AlertState(TypedDict):
    alert: str
    cause: str
    approved: bool
    result: str

def approve(s):
    answer = interrupt({"cause": s["cause"]})
    return {"approved": answer == "approve"}

g = StateGraph(AlertState)
g.add_node("detect", detect)
g.add_node("diagnose", diagnose)
g.add_node("approve", approve)
g.add_node("heal", heal)
g.add_edge(START, "detect")
g.add_edge("detect", "diagnose")
g.add_edge("diagnose", "approve")
g.add_edge("approve", "heal")
案例 2 · Lakehouse 寫入
parse → route → execute → approve → submit
from langgraph.types import interrupt

class IngestState(TypedDict):
    workspace: str
    intent: str
    yaml: str
    approved: bool
    run_id: str

def approve_yaml(s):
    answer = interrupt({"yaml": s["yaml"]})
    return {"approved": answer == "approve"}

g = StateGraph(IngestState)
g.add_node("parse", parse)
g.add_node("route", route)
g.add_node("execute", execute)
g.add_node("approve", approve_yaml)
g.add_node("submit", submit)
g.add_edge(START, "parse")
g.add_edge("execute", "approve")
g.add_edge("approve", "submit")
interrupt() 保存目前進度並暫停；收到批准後，從同一個節點繼續。

Pydantic AI：用型別檢查 Agent 輸出

Agent

@agent.tool_plain

# pip install pydantic-ai
from pydantic import BaseModel
from pydantic_ai import Agent

class HealReport(BaseModel):   # 輸出型別
    root_cause: str
    actions: list[str]
    verified: bool

agent = Agent(
    "openai:gpt-4o",
    system_prompt="你是維運工程師：收到 alert 先診斷根因、執行修復、驗證，最後寫成 issue 報告。",
    result_type=HealReport,    # 錯型別直接報錯
)

@agent.tool_plain
def run_fix(action: str) -> str:
    return execute_fix(action)  # 註冊給模型選

result = agent.run_sync("Trino 節點 alert")
print(result.output.root_cause)    # 已檢查格式
輸出欄位或型別不符，就直接失敗，不往下執行。

from crewai import Agent, Task, Crew, Process

diagnoser = Agent(
    role="異常診斷員",
    goal="分析 alert 找出根因",
    tools=[query_logs],          # 給這個角色的工具
)
fixer = Agent(
    role="修復員",
    goal="執行修復並產出 issue 報告",
)

t1 = Task(description="分析 Trino 節點 alert",
          expected_output="根因分析", agent=diagnoser)
t2 = Task(description="執行修復並驗證",
          expected_output="issue 報告", agent=fixer)

crew = Crew(agents=[diagnoser, fixer],
            tasks=[t1, t2],
            process=Process.sequential)  # 或 hierarchical
result = crew.kickoff()
每個角色只拿需要的工具，上一個任務的結果交給下一個。
